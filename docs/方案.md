# 忆栈 MemStack —— 竞品项目方案

> 工作代号：**忆栈 / MemStack**（备选：码忆 CodeRecall、复栈 ReStack）
> 一句话：**完整支持代码块渲染（Markdown + 语法高亮）的开源间隔重复记忆卡应用**。Rust 后端 + Rust 前端，本地数据永远归你。
> 版本：v0.2（2025-08）

---

## 0. 为什么要做

### 0.1 友商的问题（我们的切入点）

先看现象，再看现象背后的东西。友商的产品呈现为四个问题：

| 问题 | 具体表现 |
|---|---|
| 不支持代码块 | 没有 fenced code、没有语法高亮，背命令/API/SQL/算法模板等于残废 |
| 封闭格式 | 卡片数据导不干净、导出受限制，用户被绑定在平台上 |
| 付费墙切得稀碎 | 学习上限、同步、额外词库拆开卖，核心功能都要订阅 |
| 话术大于功能 | 不谈功能谈“记忆理念”，文档没一句能解决实际问题 |

现象背后是同一件事：**一个以“帮助记忆”为目的的工具，在实际运行中处处限制记忆。** 工具的使用价值和它的变现方式发生了分离——数据封闭不是技术必需（导出功能一天就能做好），而是商业必需：把用户的学习记录变成锁定用户的资产，把完整的使用价值切成学习上限、词库、同步三个收费口。文绉绉的“理念”正是这层关系上的包装：形式越文艺，越说明内容上没什么可谈的。

辩证地看，这不全是坏事：友商用十年时间证明了间隔重复有真实而稳定的需求，也立起了“体验要顺滑”的标准。它的成就里包含着它的局限，我们要做的是对它的扬弃——保留它验证过的合理内核（SRS 方法论、轻量复习体验），丢掉封闭格式与付费墙，在开放与免费的基础上重建。它今天的用户规模更多来自渠道与运营的积累，而非产品能力本身；这种体量与品质的错位，正是后来者的机会。

**技术人群的间隔重复需求，至今没有一款像样的产品在服务。**

### 0.2 目标用户

1. **程序员/CS 学生**：算法模板、设计模式、Linux 命令、SQL、API 签名、面试八股
2. **对数据所有权敏感的人**：需要开放格式、可迁移、可自建同步
3. **存量语言学习者**中对友商付费墙不满的用户

### 0.3 市场机会

- Anki 开源但 UI 停留在十年前、同步体验差、配置是地狱；代码高亮要靠插件勉强凑
- Obsidian + Spaced Repetition 插件路线体验割裂，移动端基本不可用
- **没有一款“为代码而生的 SRS”**。这个位置是空的。

## 1. 定位与原则

**项目原则第 0 条：功能说话，不写小作文。** 文档写人话，每句话能落地；理念只出现在这半行里，之后不再提。

1. **本地优先**：全部核心功能离线可用，账号只为同步存在
2. **开放格式**：SQLite + Markdown，任何数据都能完整导出，随时跑路
3. **算法透明**：FSRS（开源算法，Anki 同款），参数可看可调，复习记录全量导出可复算
4. **键盘优先**：整个复习流不碰鼠标
5. **代码是内容**：语法高亮、行号、复制按钮、LaTeX 公式，开箱即用

## 2. 功能范围

### 2.1 卡片示例（这是产品灵魂，放最前面）

````markdown
---
deck: 算法
tags: [leetcode, 二分]
---

Q: 二分查找左边界模板，循环不变式是什么？

```rust
fn lower_bound(arr: &[i32], x: i32) -> usize {
    let (mut l, mut r) = (0, arr.len());
    while l < r {
        let m = l + (r - l) / 2;
        if arr[m] < x { l = m + 1 } else { r = m }
    }
    l
}
```

A: 区间 [l, r) 内 arr[l..r] 全部可能 >= x；l == r 时收敛。
````

### 2.2 MVP（桌面端 + CLI，6-8 周）

1. **Markdown 卡片**：fenced code 语法高亮（含行号/一键复制）、行内代码、LaTeX、表格、图片
2. **FSRS 调度**：基于 fsrs crate，内置预设参数，支持一键参数优化
3. **键盘复习流**：Space 翻答案、1-4 评分（重来/困难/良好/简单）、撤销、每日上限、暂停牌组
4. **三种题型**：基础问答 / 填空 cloze / **代码填空（code cloze）**——输入补全后与标准答案做本地 diff 对比
5. **牌组管理**：deck / tag / 全文搜索 / 暂停与归档
6. **导入**：Anki .apkg、CSV/TSV、Markdown 文件夹（批量导入）
7. **存储**：SQLite（WAL 模式），单文件数据库
8. **同步 MVP**：文件级同步——直接放 WebDAV/坚果云/Syncthing/iCloud 目录里，不依赖任何服务
9. **CLI/TUI**：终端里创建卡片、复习、看统计（ratatui），可脚本化批量造卡

### 2.3 V1

- **自建同步服务**（axum）：账号体系、增量同步、多设备冲突处理，docker 一条命令部署
- **统计面板**：预测曲线、复习负荷、热力图、牌组健康度
- **卡片模板系统**：前端/后端/语言学习等预设模板
- **编辑器插件**：Neovim / VSCode 划词造卡

### 2.4 V2

- **移动端**：Rust core 复用 + 轻壳（Tauri Mobile 或 UniFFI + 原生壳）
- 社区牌组分享、插件系统

## 3. 技术选型

### 3.1 总览

| 组件 | 选择 | 备选 | 理由 |
|---|---|---|---|
| 调度算法 | **fsrs 6.x** | — | open-spaced-repetition 官方实现，与 Anki 同源算法，内置优化器 |
| 存储 | **SQLite + sqlx** | rusqlite | 迁移管理成熟，异步，服务端可复用 |
| 同步服务 | **axum + tokio** | actix-web | 生态与文档最好，社区最大 |
| Markdown 解析 | **pulldown-cmark** | comrak | 纯 Rust、CommonMark、事件流可分别转 HTML/纯文本 |
| 语法高亮 | **syntect**（TUI/导出用） | tree-sitter | webview 内走 highlight.js；syntect 覆盖 TUI 与导出 |
| 数学公式 | **KaTeX**（webview 内） | — | 生态最全；TUI 场景显示源码 |
| 桌面 GUI | **Tauri 2 + Leptos** | egui 0.32 | 见 3.2 |
| TUI | **ratatui** | cursive | 程序员第一界面，纯 Rust |
| CLI | **clap 4** | — | 造卡、导入、复习脚本化 |

### 3.2 桌面 GUI：两条路线（都支持，写清楚取舍）

**路线 A：Tauri 2 + Leptos（推荐）**

- 全栈 100% Rust：Leptos 编译到 WASM 跑在系统 webview 里，Rust core 以库形式嵌入，无 FFI 边界
- 代码高亮、KaTeX、富文本、图片排版**零成本**，CJK 字体由系统原生处理
- 体积 5-10 MB，跨 Win/macOS/Linux
- 代价：依赖系统 webview，不是“纯原生”渲染

**路线 B：egui 0.32（纯原生 Rust GUI）**

- 无 webview，真正的 Rust GUI，键盘流天然顺手
- syntect 高亮、自定义字体嵌入可用
- 代价：富文本/数学公式/图片排版能力弱，CJK 字体要手动打包，移动端无望

**结论**：MVP 走路线 A 快速验证产品；同时 **core 层从第一天起不依赖任何 GUI 框架**，路线 B 随时可以以 feature 分支接入，TUI 从一开始就存在——纯 Rust 洁癖用户也有归宿。两条路线共享同一个 core，切换成本被压到最小。

### 3.3 移动端路线（预留，不提前做）

- Tauri 2 Mobile（webview 壳）或 UniFFI 把 core 暴露给原生壳
- SQLite schema 与同步协议**从第一天按多端设计**，避免事后返工

### 4.2 数据模型（SQLite schema 草图）

```sql
CREATE TABLE decks (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  created_at INTEGER NOT NULL
);
CREATE TABLE notes (          -- 卡片内容层
  id INTEGER PRIMARY KEY,
  deck_id INTEGER NOT NULL,
  front_md TEXT NOT NULL,     -- 原始 Markdown
  back_md  TEXT NOT NULL,
  tags TEXT,                  -- JSON 数组
  created_at INTEGER NOT NULL
);
CREATE TABLE cards (          -- 调度层（一张 note 可生成多张卡，如 cloze）
  id INTEGER PRIMARY KEY,
  note_id INTEGER NOT NULL,
  kind INTEGER NOT NULL,      -- 1=问答 2=cloze 3=code-cloze
  due INTEGER NOT NULL,       -- 到期时间戳
  state INTEGER NOT NULL,     -- 新卡/学习/复习
  fsrs_state BLOB NOT NULL    -- FSRS 内部状态
);
CREATE TABLE review_logs (    -- 只增不改，同步冲突天然少
  id INTEGER PRIMARY KEY,
  card_id INTEGER NOT NULL,
  rating INTEGER NOT NULL,    -- 1-4
  elapsed_ms INTEGER NOT NULL,
  reviewed_at INTEGER NOT NULL
);
CREATE TABLE deck_params (    -- 每牌组 FSRS 参数
  deck_id INTEGER PRIMARY KEY,
  params BLOB NOT NULL
);
CREATE TABLE sync_meta (      -- 同步游标/变更日志
  key TEXT PRIMARY KEY,
  value BLOB NOT NULL
);
```

### 4.3 同步协议（V1）

- 每设备维护**变更日志**；review_logs 只增不改，其余表字段级 last-writer-wins
- 服务端只做存储与转发，不碰卡片内容——自建与官方托管行为完全一致
- 同步服务 docker 一条命令部署，SQLite 即可承载个人量级

### 4.4 渲染流水线

```
Markdown ──pulldown-cmark──> 事件流 ─┬─> HTML（webview 内 highlight.js + KaTeX）
                                     ├─> 纯文本降级（TUI）
                                     └─> egui 富文本（路线 B）
```

## 8. 开源与商业化

- **许可策略**：客户端（core/storage/markdown/import/cli/desktop）采用 MIT 或 Apache-2.0 双许可，使用者任选其一（Rust 社区惯例）；同步服务 server 采用 **AGPLv3**——防他人拿服务端代码跑闭源 SaaS，不伤任何终端用户体验
- **单仓落地**：同一仓库放 LICENSE-MIT、LICENSE-APACHE、LICENSE-AGPL 三份文本；各 crate 在 Cargo.toml 的 license 字段声明各自协议（客户端 "MIT OR Apache-2.0"，服务端 "AGPL-3.0-only"），README 写明对应关系；协议按 crate 生效，不按仓库生效
- **兼容性**：permissive → AGPL 单向兼容，server 链接客户端 core 合法，分发时保留其版权声明即可
- 核心功能永久免费，导出永不设限
- 收入：官方托管同步订阅（个位数美元/月级别）+ 捐赠；自建同步完全免费且体验一致
- 铁律：**本地功能永不收费**——这是对友商付费墙的正面回应，也是护城河

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| GUI 路线（Tauri/egui）选错 | core 与 UI 彻底解耦，TUI 兜底，切换成本被压到最小 |
| 万卡级渲染卡顿 | 高亮结果按卡片缓存；复习流只渲染单卡 |
| 同步冲突 | review_logs append-only + 字段级 LWW，最坏情况不丢数据 |
| FSRS 参数调优门槛 | 内置预设 + 一键优化（fsrs 自带优化器） |
| 移动端是长期短板 | schema 与同步协议按多端设计，避免返工 |
