# 忆栈 MemStack 方案

一个开源的间隔重复记忆卡应用。和市面上那些最大的不同：代码块是内容的一部分，Markdown、语法高亮、数学公式全都原生支持，不用装插件。Rust 写后端，桌面端优先，数据永远在你自己手里。

原则就一条：功能说话，不写小作文。

## 为什么要做

市面上那款主流记忆卡应用，有几个毛病：

- 不支持代码块。没有语法高亮，背命令、API、SQL、算法模板的人基本没法用。
- 数据封闭。卡片导不干净，等于人被绑在平台上。
- 付费墙切得很碎。学习上限、同步、词库分开卖，想用得爽就得订阅。
- 话术多，功能少。文档里全是"记忆理念"，实际问题一个不解决。

表面上是四个问题，背后是一件事：一个号称帮你记忆的工具，跑起来处处限制你记忆。数据封闭不是技术做不到——导出功能一天就能写完——是商业模式要求这么干。你的学习记录是锁住你的资产，完整的功能被切成几个收费口，那些文艺话术就是这层关系的包装。形式越精致，越说明内容没得谈。

换个角度看，这也不是全无价值：人家用十年证明了间隔重复有真实稳定的需求，也把"用着顺滑"的标准立了起来。我们要做的是留下合理的内核——间隔重复方法本身、轻量的复习体验——扔掉封闭格式和付费墙，在开放和免费的基础上重做一遍。它今天的用户规模更多是渠道和运营攒出来的，不是产品能力。体量大不等于东西好。

Anki 开源，但界面老旧、配置是地狱；Obsidian 加插件的路线体验割裂，移动端基本不可用。程序员背算法模板、设计模式、命令、SQL，到现在没有一款像样的工具。这个位置空着。

## 做什么

第一版（桌面加命令行，六到八周）：

- Markdown 卡片。代码块带语法高亮、行号、复制按钮；公式用 KaTeX；表格、图片正常支持。
- FSRS 调度。Anki 同款算法，参数可看可调，复习记录能全部导出复算。
- 键盘复习。空格翻答案，1-4 评分，能撤销，有每日上限。
- 三种题型：问答、填空、代码填空。代码填空就是把代码挖个洞，你补上，再和标准答案做 diff。
- 牌组、标签、搜索、暂停归档，常规功能都有。
- 导入 Anki 的 .apkg、CSV、Markdown 文件夹。
- 存储用 SQLite，单文件。第一版不做同步服务：把数据库文件放坚果云、WebDAV、Syncthing 里，多端同步就有了。
- 一个命令行版。终端里复习、批量造卡，顺手就做了。

卡片就是一个 Markdown 文件，前后两面用 --- 分开：

````markdown
---
deck: 算法
tags: [leetcode, 二分]
---

正面：二分查找左边界模板，循环不变式是什么？

```rust
fn lower_bound(arr: &[i32], x: i32) -> usize {
    let (mut l, mut r) = (0, arr.len());
    while l < r {
        let m = l + (r - l) / 2;
        if arr[m] < x { l = m + 1 } else { r = m }
    }
    l
}
```

背面：区间 [l, r) 内 arr[l..r] 全部可能 >= x，l == r 时收敛。
````

第二版：自建同步服务（axum，docker 一条命令部署）、统计面板（预测曲线、热力图）、卡片模板、Neovim 和 VSCode 划词造卡。

第三版：移动端、社区牌组、插件系统。

## 怎么实现

全 Rust，一个 workspace，客户端和服务端分开授权。

- 调度：fsrs，Rust 实现，和 Anki 同源。
- 存储：SQLite + sqlx。
- 同步服务：axum + tokio。
- Markdown：pulldown-cmark。高亮：桌面用 highlight.js，终端和导出用 syntect。
- 桌面 GUI：Tauri 2 + Leptos。全栈 Rust，webview 负责渲染，高亮和公式不用自己造轮子。
- 备选：egui。纯原生，没有 webview，但富文本、公式、图片排版都弱，先不做。
- 终端：ratatui；命令行：clap。

core 不依赖任何 GUI 框架。哪天想换 egui，只换壳。终端版从一开始就有。

结构就是一个 Cargo workspace：

```
memstack/
├── crates/core       领域模型、FSRS 调度，不碰 IO
├── crates/storage    SQLite 和迁移
├── crates/markdown   渲染（HTML / 纯文本 / 富文本）
├── crates/import     apkg、CSV、Markdown 导入
├── crates/cli        CLI + TUI
├── crates/desktop    Tauri 壳
├── crates/server     同步服务（AGPLv3）
├── frontend/         Leptos 源码
└── docs/             这份文档
```

数据表就几张：decks、notes、cards、review_logs、deck_params。复习记录只增不改，同步冲突基本没得吵。

## 许可证

客户端（core、storage、markdown、import、cli、desktop）：MIT 或 Apache-2.0，用的人自己选。Rust 生态惯例就是这样，别人集成起来没顾虑。

同步服务 server：AGPLv3。防止有人拿服务端代码改改就开闭源 SaaS。

仓库里放三份 LICENSE，各 crate 在 Cargo.toml 里声明自己那份。协议按 crate 算，不按仓库算。

## 节奏

- 两周：原型。core + SQLite + 命令行复习闭环，终端里能完整跑一遍复习。
- 六到八周：桌面 MVP。编辑器、高亮、导入、键盘流、文件级同步、统计页。验收：导入 Anki 万卡牌组不卡。
- 四到六周：同步服务。账号、增量同步、冲突处理、docker 部署。
- 之后：移动端预览，再往后是社区和插件。

## 钱的事

核心功能永远免费，导出永远不设限。收入靠官方托管同步的订阅，一个月几美元；自建同步免费，体验一样。不做广告，不卖词库，不切付费墙。

## 可能踩的坑

- GUI 路线选错：core 和 UI 解耦，终端版兜底，换壳成本很小。
- 万卡渲染卡顿：高亮结果缓存，复习流一次只渲染一张卡。
- 同步冲突：复习记录只增不改，最坏情况也不丢数据。
- 移动端是短板：表和同步协议按多端设计，不返工。
